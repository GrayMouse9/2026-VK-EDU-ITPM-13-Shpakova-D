## 3. Стек технологий и обоснование

| Слой | Технология | Почему именно она |
|---|---|---|
| Мобильный клиент | **Swift (iOS) + Kotlin (Android)** | Нативная производительность критична для анимации «раскрытия конверта» и push-уведомлений. На MVP две команды быстрее одной кросс-платформенной. |
| Веб-приложение | **React + TypeScript** | Внутренняя аудитория, быстрый CRUD, типизация защищает от ошибок при росте кодовой базы. |
| Бэкенд | **Python 3.12 + FastAPI + Gunicorn** | FastAPI ускоряет API-First (автогенерация Swagger). Скорость разработки MVP важнее экстремальной нагрузки. На пиках масштабируем горизонтально через Kubernetes. |
| Фоновые задачи | **Celery + Celery beat + Redis** | Тяжёлые операции (подбор у GDS) и отложенные задачи (раскрытие конверта за 24 часа) выносим из API, чтобы не блокировать ответы пользователю. Идемпотентность задач переживает рестарты. |
| Основная БД | **PostgreSQL 16** | ACID-транзакции — обязательны для денег и броней. JSONB-поля покрывают гибкие настройки пользователя. PostGIS — для геопоиска отелей. |
| Хранилище файлов | **S3-совместимое Object Storage** | Посадочные талоны, ваучеры, фотографии — типовая задача для объектного хранилища. |
| Точка входа | **Nginx** | HTTPS-терминирование, защита от медленных клиентов, отдача статики, кеш. Скрыт «под капотом» Бэкенда — на диаграмме контейнеров не показан как отдельная единица. |
| Платежи | **ЮKassa + СБП** | Покрывают 99% B2C в РФ; чек уходит в ОФД автоматически по 54-ФЗ. |
| Поставщики инвентаря | **Amadeus / Sabre / прямые API отелей** | Авиа — глобальные GDS, отели — гибридная схема (часть прямых партнёров, часть агрегаторов). |
| Push | **APNs (iOS) + FCM (Android)** | Индустриальный стандарт, без альтернатив. |
| Геоданные и погода | **Яндекс.Геокодер + Яндекс.Погода** | Локальные источники с лучшим покрытием РФ. |
| Наблюдаемость | **Prometheus + Grafana + Sentry** | Prometheus собирает метрики (нагрузка, ошибки), Grafana рисует по ним графики, Sentry ловит падения мобильного приложения у реальных пользователей. |
| CI/CD | **GitHub Actions + Docker + Kubernetes (Yandex Cloud)** | GitHub Actions гоняет тесты на каждое изменение, Docker упаковывает приложение в образ, Kubernetes разворачивает на серверах в Yandex Cloud. |
| E-mail | **Транзакционный почтовый провайдер** (Яндекс 360) | Доставка «конверта-сюрприза» на e-mail дублирует push (на случай, если пользователь не разрешил уведомления). Используем готовый провайдер с высокой deliverability — свой SMTP не поднимаем. |

**Принцип выбора:** «сначала работает — потом правильно — потом быстро». На MVP — Python/FastAPI и монолит с выделенными воркерами. Когда упрёмся в производительность отдельных сервисов (в первую очередь — раскрытие конверта), их можно переписать на Go без переделывания всего бэкенда.
